Inteligência Artificial Aberta para Documentos Acessíveis no Ensino Superior

O Acessília é uma iniciativa multidisciplinar de pesquisa e extensão da Universidade Federal de Goiás (UFG) com apoio de supercomputação do LaMCAD/UFG. Desenvolvido em software livre e operado pelo Núcleo de Acessibilidade da UFG, transforma apostilas, artigos e livros acadêmicos em PDF/UA, áudio narrado e HTML semântico com audiodescrição técnica para estudantes cegos e com baixa visão.

Fundamentação Científica

Pesquisa Científica & Benchmark Dr.DocBench

Como o projeto Acessília supera os limites de parsing onde ferramentas convencionais falham.

O Desafio dos Documentos Complexos

Em documentos do mundo real — especialmente artigos acadêmicos, teses e livros técnicos —, elementos visuais como equações matemáticas embutidas, tabelas sem grades, colunas duplas e notas marginais causam quebras catastróficas em leitores de tela e em extratores tradicionais de OCR.

O Acessília fundamenta sua arquitetura na superação de casos extremos de falha documentados na literatura científica, integrando segmentação de layout com Docling, OCR robusto com RapidOCR e agentes de linguagem com visão multimodal.

Alinhamento com o Benchmark Dr.DocBench

O benchmark Dr.DocBench (A Comprehensive Benchmark for Expert-Level and Difficult Document Parsing) introduziu uma metodologia rigorosa de avaliação baseada em amostragem de falhas de parsers (parser-failure-based sampling) através de 52 domínios temáticos.

O Acessília utiliza essa fundamentação para garantir que mesmo os layouts mais intrincados sejam normalizados em estruturas semânticas limpas, prontas para gerar conformidade PDF/UA (ISO 14289) e acessibilidade digital de nível superior.

Artigo Científico de Referência arXiv:2606.01393 [cs.CV / cs.CL]

Dr. DocBench: A Comprehensive Benchmark for Expert-Level and Difficult Document Parsing

Resumo de Contexto: Este benchmark especializado avalia sistemas de parsing em documentos desafiadores com múltiplas páginas, notações especializadas (fórmulas químicas e matemáticas, tabelas complexas e diagramas intrincados), servindo como base de rigor metodológico para as decisões arquiteturais do Acessília.

O Que É o Projeto Acessília?

Uma ponte tecnológica entre documentos visuais e a autonomia de leitura para pessoas cegas ou com baixa visão.

🎯

O Desafio

Milhões de documentos acadêmicos, livros, relatórios governamentais e apostilas circulam em PDFs sem marcação estrutural, imagens sem audiodescrição ou digitalizações ilegíveis para leitores de tela convencionais (como NVDA, JAWS, Orca ou VoiceOver). O resultado é a exclusão informacional direta.

💡

Nossa Solução

O Acessília decompõe o documento, reconstrói sua árvore semântica correta (títulos H1 a H6, tabelas com cabeçalhos acessíveis, listas ordenadas, fórmulas em MathML/LaTeX) e emprega modelos de linguagem para audiodescrever figuras e diagramas com precisão técnica e contexto.

Principais Capacidades

Projetado com base em padrões de acessibilidade digital e arquitetura moderna.

📑

PDF/UA Universal

Exporta PDFs etiquetados de acordo com a norma ISO 14289-1 (PDF/UA), garantindo conformidade com leitores de tela e tecnologias assistivas em qualquer plataforma.

🖼️

Audiodescrição com IA

Agentes multimodais inspecionam imagens, fotos, infográficos e esquemas gráficos, gerando descrições textuais contextuais e alt text de alto padrão.

🎧

Síntese de Voz Integrada

Gera versões em áudio (MP3) com ritmo natural e capítulos estruturados, permitindo audição contínua sem depender exclusivamente do leitor de tela do dispositivo.

🔬

Extração Docling + RapidOCR

Combina redes neurais de ponta para segmentação de layout com motores OCR rápidos, identificando colunas múltiplas, cabeçalhos, notas de rodapé e tabelas complexas.

🔒

Privacidade e Execução Local

Suporta execução 100% offline e local via Ollama, protegendo dados confidenciais ou institucionais, além de integração com OpenRouter para modelos em nuvem.

⚡

Múltiplas Interfaces

Acesse como preferir: através da API REST, de um Painel Web intuitivo, de um Bot do Telegram ágil ou via Linha de Comando (CLI).

Arquitetura Modular

Separação clara entre Domínio, Aplicação e Interfaces para máxima extensibilidade.

Camada 1

Backend & Domínio

  • Agentes de IA: Avaliação contextual e descrições visuais.
  • Clientes LLM: Abstração para Ollama, OpenRouter e APIs externas.
  • Pipeline Modular: Estágios desacoplados de extração e normalização.
  • Exportadores: Geradores nativos de PDF/UA, HTML, MP3 e DOCX.
Camada 2

API REST Núcleo

  • FastAPI assíncrona: Alta performance e documentação OpenAPI.
  • Fila de Jobs: Processamento em fila com consulta de status em tempo real.
  • Segurança: Downloads via token seguro com expiração configurável.
  • Persistência: Registro de histórico e telemetria via SQLite.
Camada 3

Frontends & Clientes

  • Painel Web: Interface acessível para envio de arquivos e acompanhamento.
  • Bot do Telegram: Envio prático de áudio ou documento pelo celular.
  • CLI (Terminal): Automatização e processamento em lote em servidores.
  • MCP Server: Integração com agentes e ferramentas externas.

Como Começar

Suba seu próprio ambiente Acessília em poucos minutos via Docker ou Poetry.

Execução com Docker

Utilize as imagens oficiais publicadas no GitHub Container Registry (ghcr.io):

Bash / Terminal 
# Baixar a imagem completa com Docling, RapidOCR e PyTorch CPU
docker pull ghcr.io/a11ydevs/acessilia:main

# Executar os serviços (API na porta 8000 e painel Web na 8001)
docker run --rm \
  --env-file .env \
  -p 8000:8000 \
  -p 8001:8001 \
  -v "$PWD/var:/app/var" \
  ghcr.io/a11ydevs/acessilia:main

Nota: Para servidores com recursos reduzidos, utilize a versão leve ghcr.io/a11ydevs/acessilia:main-slim.

Instalação com Poetry

Clone o repositório oficial e configure o ambiente com o Poetry:

Bash / Terminal 
# Clonar o repositório
git clone https://github.com/A11yDevs/acessilia.git
cd acessilia

# Instalar dependências
poetry install

# Configurar variáveis de ambiente
cp .env.example .env

# Iniciar todos os serviços (API + Web + Telegram)
poetry run python -m frontend.run

Consumindo a API REST

Envie um arquivo para processamento assíncrono via cURL:

cURL / HTTP 
# 1. Enviar documento para a fila
curl -X POST "http://localhost:8000/api/v1/jobs" \
  -F "file=@documento.pdf" \
  -F "export_formats=pdf_ua,mp3,html"

# 2. Consultar status do processamento
curl -X GET "http://localhost:8000/api/v1/jobs/{task_id}"

# 3. Baixar versão PDF/UA acessível gerada
curl -O "http://localhost:8000/api/v1/download/{token}/pdf_ua"

Perguntas Frequentes (FAQ)

Tire suas dúvidas sobre o funcionamento, acessibilidade e privacidade do Acessília.

O que é um arquivo PDF/UA e por que ele é importante? +

PDF/UA (Universal Accessibility, norma ISO 14289) é o padrão internacional que assegura que arquivos PDF sejam completamente interpretáveis por tecnologias assistivas. Ele exige etiquetas semânticas, ordem de leitura rigorosa, contraste adequado e descrição para todos os elementos não textuais.

Meus documentos enviados para processamento ficam salvos ou expostos? +

Não. Ao executar a plataforma localmente via Docker com Ollama, nenhum dado ou texto sai da sua rede corporativa ou computador pessoal. A API gerencia tokens efêmeros para download e limpa os arquivos após o ciclo de vida definido na configuração.

Como o Acessília descreve imagens complexas e equações matemáticas? +

O Acessília usa modelos de visão computacional combinados com prompts estruturados para audiodescrição técnica (seguindo diretrizes de audiodescrição para exames e materiais didáticos). Fórmulas matemáticas são extraídas e convertidas em notação semântica (como LaTeX ou MathML), permitindo navegação símbolo por símbolo no leitor de tela.

Como posso contribuir com o desenvolvimento do Acessília? +

O projeto é 100% de código aberto sob licença MIT, mantido pela organização A11yDevs. Você pode contribuir abrindo issues, sugerindo melhorias na pipeline de IA, adicionando novos exportadores ou aprimorando o suporte a leitores de tela no repositório GitHub.
